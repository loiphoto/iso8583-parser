### Task 1: Scaffolding + input cleaner

**Files:**
- Create: `package.json`, `.gitignore`, `scripts/serve.mjs`, `js/parser/cleaner.js`
- Test: `test/cleaner.test.mjs`

**Interfaces:**
- Produces: `normalizeHexDump(text: string) -> string` — continuous uppercase hex, byte-aligned, `""` when no bytes found

**The cleaner rules (pinned — the implementer does not invent these):**

Per line, in order:

0. If the line, after whitespace-stripping, matches `/^[0-9a-fA-F]+$/` and is ≥ 4 chars: treat as continuous hex (a naked hex line, no separators).
1. Else if the line matches `/^[0-9a-fA-F]{4,}[: ]/`: it is hexdump/xxd form. Drop the offset token, then take consecutive byte-tokens until the first non-byte-token — the gutter text always breaks the run, so the gutter column is ignored automatically.
2. Otherwise: split into tokens. A byte-token is exactly 2 hex chars. Take the longest run of byte-tokens separated by exactly one space, of length ≥ 2; any other token (4-digit years, words, `-`/`:` separators, gutter text) breaks the run. This is what keeps `2026-10-29 14:52:30` and `[iso]` out of the message.
3. Join accepted bytes; if the total length is odd, drop the final nibble.

### Task 3: Decoder — bitmap walker & field parser

**Files:**
- Create: `js/parser/decode.js`, `test/vectors.mjs`
- Test: `test/decode.test.mjs`

**Interfaces:**
- Consumes: `FIELDS`, `lookupField`, `lookupMti`, `lookupProcessingCode`, `lookupResponseCode` (Task 2)
- Produces: `parseMessage(hex: string, opts: { customFields?: object, encoding?: "ascii"|"bcd"|"ebcdic" } = {}) -> ParseResult`

```js
// ParseResult
{
  ok: boolean,                    // true = consumed exactly to end with no errors
  mti: string | null,
  mtiMeaning: {en, vi} | null,
  kind: "request" | "response" | "advice" | "advice-response" | "unknown",
  // kind from mti[2]: "0"→request, "1"→response, "2"→advice, "3"→advice-response
  bitmapHex: string,              // primary bitmap hex (16 chars)
  secondaryBitmap: boolean,
  fields: [ { de, name: {en,vi}, rawHex, value: string | null,
              meaning: {en,vi} | null, startByte, endByte, uncertain: boolean } ],
  errors: [ { startByte: number, message: string } ],
  consumedBytes: number,
  trailingBytes: number
}
```

**Pinned decode semantics:**

- MTI = bytes 0–4 as ASCII digits; must match `\d{4}` else `ok:false`, `mti:null`
- Primary bitmap = next 8 bytes; if its bit 1 (MSB of byte 0) is set, the next 8 bytes are the secondary bitmap
- Bit n (1–128) ↔ DE n: byte `(n-1)>>3` of the bitmap, mask `0x80 >> ((n-1)&7)`; consume fields in ascending DE order
- Field consumption: `fixed` → `len` bytes; `llvar` → 1 ASCII length digit byte then that many bytes; `lllvar` → 2 ASCII length digits then that many bytes; `unknown` → stop, push `{de, uncertain:true}` + error, `ok:false`
- Truncation: any field extending past the stream → push error, mark field uncertain, stop (review focus #3)
- ASCII (default): bytes → ASCII chars; type `b` → `value:null`, raw hex kept; `an`/`ans`/`z` values right-trimmed for display
- BCD: `n` fields unpack nibbles (high nibble first, odd nibble count pads); `an`/`ans`/`z` read as ASCII
- EBCDIC: bytes → chars via the standard EBCDIC→ASCII table; `n` fields are EBCDIC digits (0xF0–0xF9)
- Meanings: DE 3 → `lookupProcessingCode`, DE 39 → `lookupResponseCode`, MTI → `lookupMti`
- `trailingBytes` = length − consumedBytes; nonzero → `ok:false` + error

### Task 4: Message splitter

**Files:**
- Create: `js/parser/splitter.js`
- Test: `test/splitter.test.mjs`

**Interfaces:**
- Consumes: `parseMessage` (Task 3)
- Produces: `splitMessages(hex: string, opts: { manualStarts?: number[] } = {}) -> Array<{ startByte, endByte, mti: string|null, kind, hex, ok: boolean }>` (hex input = cleaned continuous hex)

**Pinned split algorithm, in order:**

1. `manualStarts` non-empty → split at those sorted byte offsets (endByte = next start − 1 or stream end); slices that fail `parseMessage` are still returned with `ok:false` and raw hex (the UI flags them)
2. Length-prefixed frames: at each byte i, L = 2-byte big-endian at i; if L ≥ 12 and `parseMessage(hex.slice(i+2, i+2+L))` ok → boundary `[i+2, i+2+L)`; if that fails and `parseMessage(hex.slice(i+7, i+7+L))` ok → boundary `[i+7, i+7+L)` (a 5-byte TPDU sits between the length header and the MTI)
3. TPDU + MTI anchor (no length header): scan for 5 bytes followed by 4 ASCII digits (0x30–0x39) whose first byte is 0x30, matching a known MTI → candidate start = TPDU start; message slice starts 5 bytes later
4. Bare MTI anchor: any position where 4 consecutive ASCII digits form a known MTI → candidate start
5. Greedy from position 0: take the earliest candidate whose `parseMessage` succeeds; resume scanning after its endByte; overlapping/failed candidates skipped
6. Zero valid candidates → one message `[0, len)` with `ok:false`
